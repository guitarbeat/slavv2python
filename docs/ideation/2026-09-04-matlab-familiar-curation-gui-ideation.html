Grounding Context

Codebase context

  • STRATEGY.md places curation GUI under Trust: operators should not relearn screens, keys, or review ritual versus MATLAB.
  • Three Python surfaces diverge: Streamlit matlab_curator (sidebar + XY projection, Escape / Ctrl+Z, Vertex→Edge→Apply, .slavv-curation.json); Qt interactive_curator.py (claims classical 2×2, almost no keyboard); napari (experimental, not four-panel).
  • MATLAB curator .m sources are often missing on this checkout; scripts/curation/launch_matlab_curator_sample.m still expects them.
  • Apply is destructive human mutation; no shared keymap module; browser is the only surface that encodes the documented two-stage ritual.

Past learnings

docs/solutions/ has almost no GUI notes; nearest related learning is rank-ramp curated energies (science path), not curator interaction parity.

External context

  • Streamlit iframe / rerun patterns limit native key capture and layout fidelity.
  • Qt and napari are stronger for desktop muscle memory; still incomplete vs STRATEGY claim language.
  • Prior art: QuPath, REAVER, MIB, OHIF — multi-view review tools with explicit interaction contracts.

Ranked Ideas

~38 raw candidates across six frames; 7 survivors after critique (basis verifier + arbitration). Jump list:

1. Sole Trust claim surface 2. Claim-matrix ADR 3. Shared keymap grammar 4. One ritual + session JSON 5. Fidelity ladder 6. Pin MATLAB .m sources 7. Interaction golden suite

1. Freeze the browser as the sole Trust “MATLAB-style” claim surface

surface-choice Confidence 88% Complexity Medium

Declare Streamlit matlab_curator the only surface allowed to market MATLAB-familiar Trust. Qt and napari stay as experimental / power-user tools with honest labels. Degraded single-view modes must not inherit the MATLAB-style Trust badge.

Basis

direct: only the browser path owns the documented Vertex→Edge→Apply ritual, Escape/Ctrl+Z, and session JSON; Qt claims “1:1” while lacking keys. reasoned: Trust language collapses if three hosts each half-claim fidelity.

Rationale

Stops marketing inflation and forces investment onto one operator path—the same move science Trust made with a single claim run root.

Downsides

Desktop users who prefer Qt lose the Trust badge; may reopen “which host?” politics until the claim matrix lands.

2. Curator Trust claim-matrix ADR — ban “1:1 MATLAB” until green

trust-verification Confidence 90% Complexity Medium

Write an ADR that lists checkable cells: layout regions, keybindings, stage ritual, Apply semantics, degraded-mode labeling. Marketing and doc strings may say “MATLAB-familiar” only when the matrix is green for the claim surface. Mirrors how Energy/Edges refuse unproven certification language.

Basis

direct: Qt already claims 1:1 without a gate; STRATEGY expanded Trust to screens/keys/workflow without a curator proof surface. reasoned: science Trust already uses evaluated proofs—GUI Trust needs an analogous bar.

Rationale

Turns a fuzzy strategy sentence into a falsifiable product contract before any large UI rewrite.

Downsides

Up-front ADR work; temporary silence on “1:1” may feel like a regression in docs.

3. Shared interaction grammar / keymap-as-data

keybindings Confidence 86% Complexity Medium

Extract Escape, undo, tool toggles, and stage Continue into a single keymap / grammar module consumed by browser (and optionally Qt later). Treat the keymap as the API of familiarity—not scattered React handlers.

Basis

direct: keys live only in the React curator; Qt is button-only. external: desktop imaging tools (QuPath-class) treat accelerators as first-class. reasoned: STRATEGY’s “without relearning” fails if grammar differs by host.

Rationale

Highest leverage on the keybindings axis and unlocks cross-host convergence without forcing layout clones first.

Downsides

Streamlit iframe limits may force a hybrid capture story; Qt/napari adapters are extra work.

4. One Vertex→Edge→Apply ritual + .slavv-curation.json interchange

review-workflow Confidence 85% Complexity Medium

Make the browser session contract the interchange for all hosts: same stages, same Continue gates, same Apply rebuild semantics. Qt/napari either speak that session or stop implying MATLAB ritual parity.

Basis

direct: CurationSessionV1 / .slavv-curation.json already exist on the browser path; other hosts bypass them. reasoned: workflow match is the STRATEGY third pillar—layout alone is insufficient.

Rationale

Unifies the operator story operators actually remember: stage order and Apply cliff.

Downsides

Porting session I/O into Qt/napari is non-trivial; may delay layout work.

5. Fidelity ladder: grammar first, then optional classical 2×2 lock

layout-fidelity Confidence 78% Complexity Medium

Do not treat pixel 2×2 as the first Trust bar. Sequence: (1) shared tools/keys/stages, (2) named layout-region contract, (3) optional classical GCI 2×2 when a host can prove it. Browser may stay sidebar+projection if grammar and ritual pass.

Basis

direct: browser already prioritizes workflow over 2×2; Qt’s 2×2 without keys fails “without relearning.” reasoned: layout lock without grammar recreates today’s Qt trap.

Rationale

Resolves the 2×2 vs sidebar fight with an ordered ladder instead of a false binary.

Downsides

Operators who equate MATLAB with the literal four-panel glass may reject grammar-first as incomplete.

6. Pin / restore MATLAB curator .m sources + compare harness

trust-verification Confidence 84% Complexity Medium

Treat missing vertex_curator.m / edge curator sources as a Trust infrastructure defect. Restore or pin them, and wire launch_matlab_curator_sample.m as the live reference for screenshot and keybinding diffs.

Basis

direct: sample launcher hard-requires sources that are absent on this checkout. reasoned: without MATLAB UI truth, Python “familiar” claims are unfalsifiable.

Rationale

Same role oracles play for science Trust—reference payload must exist on disk.

Downsides

Submodule / licensing / path hygiene; not every machine will run MATLAB.

7. Screenshot + interaction-transcript golden suite

trust-verification Confidence 80% Complexity High

Build a GUI parity harness: captured interaction transcripts and layout screenshots that can run without MATLAB on every CI host, while still being regenerable from MATLAB when sources are present. Analogous to prove-exact, but for curator interaction.

Basis

direct: no GUI parity harness today; .m often missing. external: golden-master UI testing is standard for interaction-critical tools. reasoned: claim-matrix cells need automated checks, not vibes.

Rationale

Makes idea 2 enforceable and closes the “can’t prove without MATLAB” gap.

Downsides

Highest build cost; flaky visual diffs; needs careful fixture discipline.
